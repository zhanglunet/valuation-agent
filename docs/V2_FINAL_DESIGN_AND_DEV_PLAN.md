# Valuation Agent 2.0 正式版设计方案与开发计划

## 1. 背景

`v2.0.0-beta.1` 已经完成 2.0 的第一批能力：

- `--depth deep` 深度报告入口。
- 初版可比公司分析。
- 初版财务质量分析。
- 初版增长驱动因素。
- 初版风险与反证。
- 初版待验证问题清单。

但 beta 版本仍然偏“分析骨架 + 部分数据填充”。2.0 正式版要解决三个问题：

1. 分析更全面：业务、财务、同行、估值、风险都要有实质内容。
2. 数据更可靠：公开数据要有缓存、来源、缺失处理和口径提示。
3. 报告更像投研：不仅列指标，还要形成判断、反证和下一步验证路径。

## 2. 正式版目标

2.0 正式版目标：

> 用户只输入上市公司名称、简称或 ticker，系统自动生成一份结构完整、数据可追溯、结论可复核的深度投研估值报告。

正式版必须回答：

- 这家公司靠什么业务赚钱？
- 财务质量是否支撑当前估值？
- 相比同行估值是高还是低？
- 高估或低估的原因是什么？
- 当前估值主要依赖哪些增长假设？
- 哪些情况会推翻当前估值判断？
- 还需要人工核验哪些关键问题？

## 3. Beta 到正式版差距

| 模块 | beta 状态 | 正式版要求 |
|---|---|---|
| 公司识别 | 支持名称、简称、ticker | 增加候选列表、歧义处理、更多中文别名 |
| 行情数据 | Yahoo chart 接口 | 增加缓存、失败重试、来源记录 |
| 财务数据 | 收入、净利润、股数 | 增加多期收入、利润、现金流、毛利率、资产负债指标 |
| 可比公司 | 手工同行池 + PE/PS | 扩充同行池、可比性说明、分位数、异常剔除 |
| 业务分部 | 缺失提示 | 抓取 profile / 年报摘要 / 配置 fallback，输出业务分部初版 |
| 财务质量 | 单期净利率等 | 多期趋势、现金流质量、ROE/ROA、债务压力 |
| 风险反证 | 通用规则 | 结合估值、同行、财务质量动态生成 |
| 报告 | 深度报告初版 | 增加结论分层、数据来源表、缺失项表、正式 Markdown 结构 |
| 测试 | 16 tests | 覆盖公开数据 fallback、同行池、深度报告结构和异常情况 |

## 4. 正式版功能范围

### 4.1 公司解析增强

目标：

- 用户输入中文名、英文名、简称、ticker 都能稳定解析。
- 对歧义结果返回候选，不强行选错。

开发任务：

1. 扩充 `config/company_aliases.json`。
2. 新增 `resolve_candidates(query)`。
3. `resolve_symbol(query)` 遇到多个高分候选时返回候选列表或明确提示。
4. 报告中保留解析来源：alias / search / user_input。

验收：

- 中文别名 → 港股或 A 股 ticker。
- 英文短名 → 美股 ticker。
- 多上市公司（同一实体在不同市场）→ 按配置返回首选 ticker，并保留候选。
- 未识别名称不编造，返回清晰错误。

### 4.2 数据缓存与来源追踪

目标：

- 避免每次重复请求公开接口。
- 报告能说明每个关键指标来源。

开发任务：

1. 新增 `valuation_agent/cache.py`。
2. 缓存路径：

```text
data/raw/
├── search/
├── chart/
├── financials/
└── peers/
```

3. 缓存 key 使用 `source + ticker + date`。
4. 支持 `--refresh` 强制刷新。
5. 输出数据源表。

验收：

- 第二次分析同一公司时优先读缓存。
- `--refresh` 能重新请求公开数据。
- 报告中保留行情和财务来源 URL。

### 4.3 多期财务质量分析

目标：

从单期财务摘要升级为多期趋势分析。

核心指标：

- 最近 3-5 年收入。
- 最近 3-5 年净利润。
- 收入 CAGR。
- 净利润 CAGR。
- 净利率趋势。
- 经营现金流，如果可得。
- 自由现金流，如果可得。
- 股本变化。

开发任务：

1. 扩展 Yahoo fundamentals timeseries 指标。
2. 新增 `financial_history` 数据结构。
3. 实现：
   - `revenue_growth`
   - `profit_growth`
   - `margin_trend`
   - `share_count_change`
4. 报告加入“财务质量趋势表”。

验收：

- 对至少 2 家代表性上市公司（覆盖港股和美股）能输出收入和利润多期数据。
- 数据缺失时输出缺失项，而不是空表。

### 4.4 业务分部初版

目标：

正式版不要求完美解析所有年报，但不能只写“缺失”。要尽量给出业务结构。

数据来源优先级：

1. `config/business_profiles.json` 手工维护的高质量业务分部。
2. Yahoo Search / profile 中的行业和业务描述。
3. 公司公开资料摘要。
4. 缺失提示。

开发任务：

1. 新增 `config/business_profiles.json`。
2. 新增 `business-segment-skill`。
3. 新增 `valuation_agent/business_segments.py`。
4. 对重点公司先维护分部：
   - 港股互联网平台 1-2 家。
   - 美股大型科技 1-2 家。
   - 美股 AI 芯片 1 家。
   - A 股消费龙头 1 家。
5. 报告中输出：
   - 业务分部。
   - 每个分部的角色。
   - 可验证指标。
   - 缺失字段。

验收：

- 已维护分部的公司在 `--depth deep` 报告中不再只有分部缺失提示，而是列出主要业务板块。
- 每个板块有"作用"和"待验证指标"。

### 4.5 可比公司分析正式化

目标：

可比公司分析成为 2.0 的核心含金量模块。

开发任务：

1. 扩充 `config/peer_groups.json`：
   - 港股互联网。
   - 美股大型科技。
   - AI 芯片。
   - 新能源车。
   - A 股白酒。
   - 企业软件。
   - 云服务。
2. 增加可比性说明字段：

```json
{
  "ticker": "<TICKER>",
  "reason": "<可比原因，如同为某行业平台公司，具备生态和业务可比性>",
  "strength": "strong"
}
```

3. 计算：
   - PE 中位数。
   - PS 中位数。
   - 净利率中位数。
   - 目标公司分位数。
   - 异常值剔除。
4. 报告输出“为什么可比”和“为什么不可完全可比”。

验收：

- 至少覆盖 3 个行业（互联网平台、大型科技、消费龙头），每个行业至少一个可用同行池。
- 同行表不能只有 ticker，要有可比原因。
- 极端 PE 或负利润公司要标记，而不是直接污染中位数。

### 4.6 风险与反证正式化

目标：

风险不再只是通用模板，而是根据实际数据动态生成。

规则来源：

- 估值倍数。
- 同行位置。
- 净利率。
- 收入增长趋势。
- 业务分部缺失。
- 数据缺失程度。

开发任务：

1. 新增风险规则配置 `config/risk_rules.json`。
2. 实现风险分级：
   - high
   - medium
   - low
3. 每个风险输出：
   - 触发原因。
   - 影响路径。
   - 观察指标。
   - 反证条件。

验收：

- 高 PE 公司自动提示估值回撤风险。
- 低利润率公司自动提示利润转化风险。
- 同行高估公司自动提示增长兑现压力。

### 4.7 深度报告正式模板

正式版报告结构：

```markdown
# 公司深度投研估值分析报告

## 1. 核心结论
## 2. 公司与市场概览
## 3. 业务分部拆解
## 4. 财务质量与趋势
## 5. 增长驱动因素
## 6. 可比公司分析
## 7. 估值分析与交叉验证
## 8. 情景与敏感性分析
## 9. 风险与反证
## 10. 待验证问题清单
## 11. 数据来源、缺失项与免责声明
```

正式版要求：

- 核心结论必须有判断，不只是复述数据。
- 可比公司必须有解释。
- 缺失数据必须集中列出。
- 风险必须有反证条件。
- 末尾必须有数据来源表。

## 5. 开发阶段

### Phase 1：数据缓存和多期财务，2-3 天

任务：

- 新增缓存模块。
- 扩展 financial timeseries。
- 新增多期财务质量分析。
- 更新测试。

交付：

- `cache.py`
- `financial_history`
- 财务趋势表。

### Phase 2：业务分部和同行池，3-4 天

任务：

- 新增 `business_profiles.json`。
- 实现 `business_segments.py`。
- 扩充 `peer_groups.json`。
- 同行可比性说明。

交付：

- `business-segment-skill`
- 可比公司原因说明。
- 重点公司分部 profile。

### Phase 3：风险规则和正式深度报告，2-3 天

任务：

- 新增 `risk_rules.json`。
- 动态风险规则。
- 反证条件生成。
- 正式报告模板。

交付：

- 风险规则引擎。
- 正式深度报告。

### Phase 4：质量验收和正式发布，1-2 天

任务：

- 完整回归测试。
- 用至少 5 家代表性上市公司验收，覆盖以下行业各 1 家：
  - 港股互联网平台。
  - 美股大型科技。
  - 美股 AI 芯片。
  - A 股消费龙头。
  - A 股新能源车。
- 修正文档。
- 发布 `v2.0.0`。

## 6. 正式版验收标准

### 6.1 功能验收

以下命令必须可用：

```bash
python3 -m valuation_agent.cli generate-report --query <company-cn> --depth deep
python3 -m valuation_agent.cli generate-report --query <company-us> --depth deep
python3 -m valuation_agent.cli generate-report --query <company-a-share> --depth deep
```

报告必须包含：

- 业务分部。
- 多期财务质量。
- 可比公司和可比原因。
- 估值倍数和同行中位数。
- 风险与反证。
- 待验证问题。
- 数据来源和缺失项。

### 6.2 质量验收

报告不能出现：

- 编造业务分部。
- 没有来源的关键数据。
- 只有框架、没有具体判断。
- 可比公司无解释。
- 风险全是模板化空话。

### 6.3 测试验收

正式版测试数量目标：

- 不少于 30 个测试。

新增测试：

- 缓存读写。
- 财务多期趋势。
- 业务分部 profile。
- 同行池选择。
- 同行异常值处理。
- 风险规则触发。
- 深度报告结构。
- 中文别名解析。
- 公开数据失败 fallback。

## 8. 开发优先级

必须先做：

1. 多期财务质量。
2. 同行可比性说明。
3. 业务分部 profile。
4. 风险规则引擎。
5. 正式深度报告模板。

可以后做：

- 年报 PDF 全文解析。
- DOCX / PPTX。
- DCF 完整模型。
- SQLite 持久化。

## 9. 设计原则

- 宁可提示缺失，不编造。
- 宁可同行少而准，不塞弱相关公司。
- 所有判断尽量绑定数据、同行或规则。
- 自动数据只能辅助，正式投研必须人工复核。
- 2.0 正式版要让报告有“投研判断”，不只是“计算结果”。
